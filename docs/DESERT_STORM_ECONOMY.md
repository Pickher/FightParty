# 沙漠风暴地图比例与主对抗经济（0.10.0）

本轮依据仓库 `reference/desert-storm/` 的实际地图包，按主对抗规则接入当前单人对战。规则唯一来源为 `data/rules.json`；经济状态和结算由 `scripts/economy/desert_storm_economy.gd` 管理，武器与兵种数值保持原配置。

## 地图坐标

原图地形208×208；主交战区域 `Entire Field` 的边界为(6,39)～(202,157)，所以当前战场采用 **196×118格**，而非把外围六位玩家布阵区域也当成战场。将原图坐标平移(-6,-39)，双方按场地中心点对称：

| 点位 | 我方 | 敌方 |
| --- | --- | --- |
| 基地（0.11.2对调后） | (26.5,59) | (169.5,59) |
| 出兵点（0.11.2对调后） | (30,41) | (166,77) |
| 宝库/前哨 | (62,59) | (134,59) |
| 防御塔旧候选位（旧战报兼容） | (35,46) | (161,72) |
| 中央资源井 | (98,59) | 共用 |

原始基地、前哨、出生点来自 `Objects`；0.11.2按用户要求交换基地和出兵坐标，详见[本次调整](DEFENSES_0_11_2.md)。0.11.1起玩家通过战场点选防御塔位置，塔身必须完全位于己方半场内，不能重叠基地或建筑；每方仍可建一座。上表塔坐标只保留为旧战报候选，不限制玩家选址。电脑优先建在己方宝库前方6格，通过同一校验；基地自带反击继续与基地合体。原图中央 `Battle Zone` 为40×40、`Center Circle` 半径18；这些是区域尺度，**占领实际范围为2.5**。

兵营继续使用18×8组槽位，出生队形中心铺在24×24区域，组内单位仍按本身尺寸和碰撞留距。无目标时部队依次向中央井、敌方宝库、敌方基地推进；发现敌人后沿用现有锁定与攻击逻辑，途经点不会被当成可攻击目标。默认相机显示中央走廊；全图按宽高同时适配，保持格子和模型的真实比例。

本轮重设比例和关键点位，没有重建SC2悬崖、坡道、阻挡和寻路网格。外围多人布阵区仍以兵营界面表达，没有引入3v3轮流出兵。

## 基础经济

| 项目 | 当前实现 | 参考依据 |
| --- | --- | --- |
| 初始矿物 | 推荐200，可在开局设置调整 | `Timerinitialize`明确额外发放200；本项目以它作为初始钱包，不叠加SC2引擎初始资源或阵营奖励 |
| 收入节拍 | 每3个游戏秒 | `每3秒一次矿物收入`触发器 |
| 第0～10波 | 每次30矿 | `gv_paycheck=30`、`gv_incomeLevel=1` |
| 第11～40波 | 每次60矿 | 第11波将矿/气收入同时乘2 |
| 第41～63波 | 每次120矿 | 主对抗第41波再次乘2 |
| 第64波 | 停止所有周期收入 | 第64波关闭矿物收入触发器；本项目同时停止气厂分流收入 |
| 中央井 | 第10波开放，控制方每次额外3矿 | `Battle60`第10波启用；每3秒收入触发器 |
| 击杀 | 无通用矿物奖励 | 不引入PVE和指挥官特殊奖励 |
| 摧毁宝库 | 攻击方+1灵核，取消旧400矿奖励 | 原图两个前哨死亡触发器分别增加对方`c_playerPropCustom` |

**以Galaxy主对抗脚本为准**：气厂旧中文说明的第41波“9/3秒”与主脚本实际二次翻倍不一致，因此这里每座第41波为12气/3秒，基础收入120。合作模式`0011`的阶段和中央井开放波次不同，本轮不采用。

首波准备65秒，之后推荐每45秒出兵；保留本项目双边同时出兵。原图第61波包含延长准备、等待、清场等多条触发器链；当前没有移植那套终局演出及临时停薪，只保留当前最终波战斗流程和第64波停薪。自定义出兵间隔仅影响时间长度，收入升级始终按波次触发。

## 中央控制

资源井不加入单位表，不可攻击、不阻挡移动。每3秒检查2.5格内的存活正规部队，空地单位均可占领，建筑、工人和召唤物不能占领。原图用自动施法挑选单位，本项目明确用双方最近单位比较；双方等距保持原归属，避免数组顺序偏向某方。无人靠近时也保留上一次归属，直到另一方夺取。归属改变写入战报，地图用颜色显示。

## 气厂、瓦斯、灵核

- 气厂免费，每座把当前阶段基础矿物收入的10%等额转成瓦斯，**不是额外生成资源**。0～3座起步，第32波扩为最多6座；拆除恢复后续矿物收入，不影响已持有瓦斯。
- 例如第11波2座气厂：基础60分为48矿+12气；若还控制中央井，则每3秒实际51矿+12气。中央额外3矿不参与分流。
- `NSKXP_Requirement_GASLimit`的建造前计数检查为≤2/≤5，故实际最大数量为3/6；扩容升级在主脚本第32波授予，不是第35波。
- 当前没有指挥官阵营，因此采用原图`GastoMineralNorace`的规则：全部瓦斯按1:1换为矿物，不限次数。没有套用有阵营版本的一次性充能限制。
- 原图`gv_gASMAX`用于脚本批量赋气的上限，不能据此推断自然收入的钱包上限；此处不额外限制瓦斯储存。
- 灵核作为独立资源/战绩记录，显示于HUD和战报。原图还将它用于阵营、成长与结算系统；当前未引入这些系统，不自行编造兑换率或单位灵核价格。
- 气厂以经济面板中的建造/拆除操作表达，立即调整后续分流；没有另建实体气厂、建造进度或SC2供能/科技树。0.11.0起，已映射部队按原图明确的矿/气价格乘组数购买；多资源扣费和未出场退款一起校验，详见[兵种接入](DESERT_STORM_UNITS.md)。

界面兵营下方增加“经济”按钮，查看当前收入、中央控制、气厂数量，执行分流与兑换。面板打开暂停计时，和说明页一致；双方收入使用同一套规则，电脑在每次收入后按真实钱包购买，不加隐藏补贴。气厂和兑换动作经`BattleSim.apply_action()`写入战报；快照只公开查看者本人的瓦斯、灵核和气厂，中央控制公开。

旧版存档中的开局资金/波次参数不会自动覆盖新推荐值：匹配经济设置版本后才重新载入本版自定义设置，种族、音量和兵营保存仍保留。
