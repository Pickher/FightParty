## 性能（`--perf`，仅作参考）

| 项 | 结果 |
| --- | --- |
| crowd_perf | 双方 130 + 131 个单位，3999 tick；平均 39.97 ms/tick，最差 115.36 ms，峰值 586 个单位 |
| test_sim 压力 | 200 个高血量单位 600 tick，约 11.9 ms/tick |
| render_perf | 152 个单位时 7.60 FPS |

这些数字在云端共享 CPU 上测得。render_perf 在无界面模式下没有真实 GPU 渲染，**不代表实际帧率**。crowd_perf 最差帧超过 20 tick/秒对应的 50 ms 预算，大混战时可能掉帧，需要在用户机器上复测。

## 测试输出中的提示（不算失败）

- **WARN**：四族起始军队的花费都超过默认起始矿 200（人族 560、虫族 680、神族 1110、凋零 600），所以默认对局开局兵营为空。
- **INFO**：神族、凋零的镜像长局分别在第 1731、1766 tick 出现分歧，原因是中心对称坐标上的 float32 取整误差。短局镜像测试结果完全一致。
- **COUNTER**：8 组等预算克制对局只检查“换边结果一致”，胜负只打印。当前只有“雷兽对步枪兵”和“维京对重甲空军”按设计取胜。“破甲特工对重甲”“步枪兵对轻甲”“溅射对虫群”“攻城压制特工”“火焰兵对轻甲近战”“不朽者对重甲”这 6 组设计上的克制方都输了。这是平衡问题，不是规则错误。
