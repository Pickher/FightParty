# 特战队员动画接入与协作交接

## 存放与交付

GitHub 仓库：`Pickher/FightParty`。
美术分支：`art/rifle-animation-sample`。
本分支已实现游戏内播放；合并后即可随 Godot 项目运行，不需要联网下载资源，也不需要安装 Blender。

- 运行资源：`assets/units/rifle/{idle,move,fire,death}.png` 和对应 `.import` 设置。
- 动画播放器：`scripts/rifle_visual.gd`。
- 入口接线：`scripts/main.gd` 中所有 `RifleVisual` / `rifle_visual` 引用。
- 规格：`assets/units/rifle/manifest.json`、`docs/unit-art-spec.md`。
- 可编辑模型：`assets/units/rifle/source/special_ops.blend`；`source/.gdignore` 防止运行时导入模型。
- Blender / Pillow 仅在重做美术时需要，玩家不需要。

## 框架侧怎么使用

推荐合并整个分支，不要只拷贝 PNG：播放器和入口接线也是必需的。
合并前保存框架分支现有工作；若 `main.gd` 冲突，应逐段保留框架功能并加入下列表现层接线，不能用美术分支整文件覆盖框架版本。

1. 初始化 `RifleVisual.new()`，新局调用 `reset()`。
2. 非暂停、非后台、非帮助状态更新动画时钟。
3. 模拟步进前记录步枪兵身份/位置，并调用 `observe()`；消费已有事件时调用 `event()`；步进后再次 `observe()`。
4. 战场先绘制短暂死亡表现，再在原单位位置绘制角色；未揭示敌军仍走问号绘制分支。
5. 单位图标用同一个等待动画；血条、阵营圈等原有信息仍由主界面绘制。

本分支继续使用内部 ID `rifle`，没有修改 `data/units.json`。
只把中文显示名改成“特战队员”，不需要修改播放器。
如果框架侧连内部 ID 一起改了，需同步 `main.gd` 和 `rifle_visual.gd` 中的 `rifle` 判断；资源目录可以继续沿用，避免无必要的文件迁移。

合并后在 Godot 打开项目，等待资源导入；正常启动游戏即可看到配兵图标和场上特战队员的四组动画。已导出的旧 EXE / APK 不会自动更新，需要用合并后的项目重新导出。

## 职责与限制

美术侧负责模型、图集、动画播放与表现层接线，已在本分支实现。
框架侧负责合并到它正在开发的分支，保留同期入口改动和名称更新；不必重新实现播放器。
战斗规则、伤害、攻速、移动速度和判定范围不变。

现有攻击事件缺少攻击者 ID，播放器按同队/兵种/来源位置匹配，完全重叠单位存在表现歧义；死亡缺少完整致死来源，击飞方向用可识别攻击来源或朝向回退。不增加伤害类型或规则字段。

验证仅包括 304 帧图集尺寸与边界、动作帧差异、Godot 编辑器资源导入与脚本解析。遵照用户要求，没有运行模拟测试，也没有把导入成功宣称为实战验证。
