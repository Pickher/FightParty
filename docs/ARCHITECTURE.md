# 架构与接口

## 分层

`data` 是带版本的兵种与规则配置；`Catalog` 负责加载与默认阵容。

`BattleSim` 是 RefCounted 对象，不依赖 SceneTree、Node、物理引擎或画面，包含全部预算校验、波次、单位状态、固定步模拟和结算。测试可在 Godot headless 模式下运行。

`CommanderAI` 只接收上一波公开阵容、预算和本地伪随机生成器，输出普通阵容数据。`main.gd` 是本地对局控制与表现适配器：接收点击、提交阵容、调度固定步、绘制快照、呈现事件和保存设置。它不计算伤害。

## 最小接口

- 阵容：`Array[{kind: String, cell: int}]`，cell 为 row×6+column，允许空数组。
- `submit_formation(team, formation) -> String`：成功返回空串，失败返回原因，原提交保持不变。深拷贝输入，防止调用方随后改动影响待出兵阵容。
- `validate_formation(formation, allowed_budget)`：AI、玩家和测试共享校验。
- `step() -> Array[Dictionary]`：推进一个 0.05 秒模拟步，产生 wave、attack、damage、death、expired、base_damage、ended 事件。结束后的 step 不再推进。
- `get_snapshot(viewer)`：深拷贝 tick、wave、budget、bases、units、双方上一波阵容、查看方自己的下一波阵容与胜负，不含敌方待出兵阵容。
- `CommanderAI.choose(last_enemy, budget)`：返回合法网格阵容。调用者不得传入未公开信息。

单位状态包括稳定 ID、team、kind、当前位置/上一步位置、hp、cooldown、born tick。表现层以模拟余量在 prev 与 pos 之间插值，绘制的形状、颜色、血条和弹道不参与命中判定。

## 每步顺序与公平

1. 增加 tick，撤离达到 90 秒的单位，保存上一位置。
2. 到达波次边界且未达到总时限时，从双方阵容同时创建单位，并写入波次记录。
3. 按 80×80 空间桶索引单位。寻敌半径 290，正常单位取最近敌人，狙击手对射程内脆弱目标加权。
4. 以同一份步初状态决定所有单位的移动和攻击，累计伤害与基地伤害。
5. 一次性应用位置、伤害、死亡与击杀，再判断双方基地和时间结算。

同一步死亡单位仍可完成已决定的攻击；不会因为先处理我方就阻止敌方开火。分离向量基于旧位置，避免原地依次更新导致方向偏差。距离相同以稳定 ID 决定，镜像对局测试检查左右一致性。浮点与版本差异仍可能影响跨平台重放，不承诺跨架构确定性锁步。

正常对局在最高预算下每方每波至多 24 个蜂群，90 秒寿命使最多三波共存，通常不超过 144 单位。200 单位压力测试故意超过正常上限，为性能留出余量。

## 保存与复现

Godot `user://settings.cfg` 保存音量与最近阵容；`user://last_match.json` 保存规则版本、种子、每波 tick/预算/阵容和结束结果。只保留最近一局；无云端上传。文件写失败时提示，游戏仍可继续。Windows 的 user:// 通常位于 `%APPDATA%/Godot/app_userdata/FightParty`。

`tests/replay.gd` 读入记录，在原波次时刻提交双方阵容并推进模拟，比较最终结果。相同引擎、相同数据版本是复现前提；配置版本不匹配直接拒绝。

## 未来联机边界

未来以独立 Godot headless 进程运行相同模拟核心。客户端只上报阵容，服务端按玩家身份、轮次、预算和占格校验并确认；服务端广播权威状态和事件，客户端插值。不能信任客户端报送的伤害、资源、时间或胜负。

届时需要新增房间生命周期、轮次锁定、超时沿用阵容、连接恢复与协议版本管理。这些功能首版仅预留边界，不包含伪装成可用后端的空实现，不宣称已有联网防作弊能力。
