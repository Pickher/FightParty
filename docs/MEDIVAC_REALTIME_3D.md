# 医疗机实时 3D 战场表现（本地待运行验收）

基于 `cloud/test` `b75d8ec`，没有合入另一份未推送的网格/实体间距修改。本次仅表现层，不更改购买、治疗、目标、移动速度、碰撞、伤害、死亡时序或战报规则，故不增加规则版本。

## 架构与回退

- 仍是 2D 游戏。已有不透明 2D 战场 SubViewport 保持 `disable_3d=true`；另建**一个**透明 SubViewport + 独立 World3D，所有可见医疗机共享。不是每单位一个 viewport，也不重建战场为 3D。
- 使用用户现有 `assets/models/medivac/medivac.glb`（6056 三角形、4701 顶点、单材质/纹理），不改模型或贴图，不调用 Tripo、不提取星际资产。模型实际导入 AABB 用于居中/缩放，不能把 Blender 精灵 metadata 中的 Z-up 包围盒当 Godot Y-up。
- 相机正交俯视，以战场局部屏幕坐标映射 X/Z；明确 `KEEP_HEIGHT`，相机尺寸对应战场高度。跟随 `unit.prev.lerp(unit.pos, alpha)`、相机缩放和平移，不使用整个窗口尺寸。
- 战场绘制顺序：原背景/特效、普通单位及模型回退图、透明 3D 飞机层及其实际医疗连线、原生命/能量/状态覆盖层。敌方隐藏分支先于实例创建；不从隐藏单位创建医疗机/死亡残骸。商店和部队配置继续使用已存在的 2D 精灵。
- `ENABLED=false` 可在源码中关闭 3D 作性能对比。模型无法作为 PackedScene 载入/缺资源/包围盒无效时使用旧 2D；超过数量上限同样显示 2D。**不能静态检测 GPU 上“纹理为空/驱动异常”这类失败**，不宣称已自动兜底所有显卡问题。

## 四种表现

1. **转向**：按实际步进位移方向平滑转向，重新进入视野时从当前运动方向初始化；停下保持朝向，不改变单位行军目标。
2. **飞行**：轻微俯仰、随转弯侧倾、低幅悬浮、移动时双尾喷光。无新加速、装载或运输机制。坐标只写渲染 Node3D。
3. **医疗**：只读取现有 `active_beams`。有真实治疗束才亮绿灯；该医疗机的原 2D 连线跳过一次，再从同一插值/悬浮机体锚点连到对应目标。保留阵营颜色和两个目标，不另造治疗计时或重复画一套束；无 3D 的单位继续原路径。
4. **被击毁**：主线程在每个模拟 tick 前缓存已知医疗机 ID/位置，收到真正 `death` 事件才触发约 0.65 秒翻滚缩小残机和约 1 秒淡出火光/碎屑标记。并非预制碎裂骨骼动画；当 tick 内刚生成又死亡而不存在步前快照时，不猜测其类型。没有新伤害/实体碎片。

暂停、后台、帮助、经济、部队配置、初始设置和未开始时冻结表现时钟，但仍同步镜头/隐藏状态。新对局清空实例、ID、死亡效果并先隐藏后释放，避免上局残机串入；缓存是单局、渲染专用。

## 性能边界

同时最多 32 架可见实时模型 + 12 个短残机，视野外清理，超额使用已有精灵。共享渲染目标最长边 1024，保持战场宽高比；关闭 MSAA/阴影，无实时物理、导航、计算着色器、CompositorEffect 或独立粒子系统。材质采用普通 PBR/简单不受光发光几何，面向 Windows Compatibility 和 Android Mobile，但实际驱动表现与帧率仍须实机确认。静态上限不是性能测量结论。
